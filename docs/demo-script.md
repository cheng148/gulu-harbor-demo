# 咕噜港演示脚本

## 一分钟说明

咕噜港第一版是移动端优先的Web App Demo。完整平台外壳可以浏览，但真正做深的是AI选宠顾问：它通过少量多轮对话了解用户，再从预置的模拟合作商家候选中给出“宠物方向 + 具体个体”两层建议。平台不直接卖宠物，也不保证某个品种或个体一定健康、亲人或适合所有人。

## 推荐演示顺序

1. 从首页点击“选宠”进入AI顾问。
2. 输入：“我想认识一只成年英国短毛猫，偏中等体型和短毛。”
3. 回答时间问题：“工作日能留出一些时间，希望活动量不用太高。”
4. 回答相处问题：“我喜欢安静一点的互动，待在附近陪着就很好。”
5. 回答负担问题：“我能接受规律梳毛和中等花费，没有绝对不能接受的日常负担。”
6. 推荐前确认：“猫狗都不过敏。”
7. 展示方向和具体候选两个层次，并指出页面只显示“很合拍／值得认识／需要磨合”，不会显示内部数字分。
8. 修改一个条件并重新推荐，说明评分与排序由可测试代码完成，不由模型自由决定。
9. 打开市场、用品、社区和“我的”，说明这些是可点击前端原型；支付、真实下单、发帖、会员开通和联系商家尚未开放。

## 如何解释DeepSeek与Mock

- 真人演示使用`DeepSeek-V4-Flash-0731`，API调用名为`deepseek-v4-flash`。
- 自动化测试使用固定回答的Mock模型，所以每次测试结果可重复，也不会消耗API费用。
- DeepSeek负责理解用户自然语言和把追问说得自然；硬约束、追问选择、候选过滤、评分和排序由代码控制。
- T35已验证5轮真人对话，以及单独的推荐解释和安全复核调用；T35B随后将两步接入主API，并用Mock和手机浏览器验证。接线后尚未再次运行真人DeepSeek完整流程，这一点必须如实说明。

## 演示前检查

- 不展示或朗读`.env`与API Key。
- 使用Mock演示时说明它是稳定演示模式；使用DeepSeek时说明会产生少量费用且回答可能有波动。
- 确认页面标有“Demo模拟数据，不代表真实在售”。
- 不把公开手机原型网址说成已经部署完整FastAPI与DeepSeek后端。
