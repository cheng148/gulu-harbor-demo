## 1. Objective

### 1.1 建设目标

建设一个具有完整产品观感的“咕噜港”宠物服务Web Demo：

- 首页、宠物市场、宠物用品、社区、会员中心和“我的”构成可浏览、可点击的前端原型。
- “AI选宠顾问”是真实实现的多轮对话Agent，能够动态澄清需求、识别硬约束、检索知识、匹配方向与具体宠物，并解释建议。
- 交易、支付、合同、物流、真实发帖、真实商家沟通和会员付费不建设后台能力，相关动作必须提示“Demo演示功能，暂未开放”。

### 1.2 核心用户

首版核心用户是缺少养宠经验、无法一次说清选宠条件的新手养宠人。繁育者、转让者和资深养宠人只属于历史平台设想，不是首版Agent优化对象。

### 1.3 用户价值

帮助用户从“我想养一只可爱的宠物”逐步走到：

- 看清自己的住房、家庭、健康、时间和预算条件。
- 区分不可妥协的硬约束与可以权衡的软偏好。
- 先理解适合的品种/类型方向，再查看Demo中可进一步了解的具体个体。
- 同时看见适合点、负担、风险和不匹配点。
- 在必要时接受“暂不建议养宠”或“先解决前置条件”的诚实结论。

### 1.4 非目标

- 不建设完整电商、支付、合同、物流、账户或长期历史系统。
- 不接入真实商家、用户、宠物、订单或交易数据。
- 不保证品种或个体的性格、健康和行为。
- 不提供疾病诊断、治疗或替代兽医的建议。
- 不训练或微调模型。
- 不建设全自主、无边界的开放式Agent。
- 不把原策划书中的旧算法、旧技术栈或商业承诺迁入当前实现。

## 3. 产品概念与术语

- Agent：能保存多轮状态、根据当前情况决定下一步，并调用确定性业务能力的对话顾问，不是固定顺序聊天问卷。
- 槽位：画像中的一个结构化字段，例如“是否允许养宠”。
- 硬约束：违反后不能靠其他偏好或高分抵消的条件。
- 品种/类型方向：对更适合哪类宠物的上层建议，可以是品种，也可以是“成年短毛家猫”等类型。
- 具体宠物档案：本地数据集中真实存在的虚构个体记录。
- 内部匹配分：仅供排序、测试和评测的0至100数字，不向页面或公共API暴露。
- 匹配等级：用户可见的“较匹配”“可考虑”“需谨慎”。
- 最终建议：关键条件已确认且无未解决阻断项。
- 暂定建议：用户要求直接推荐或非阻断信息未完整确认，必须展示待确认项。
- 暂不建议：当前条件存在无法安全绕过的阻断项，或没有通过硬约束的合理候选。

## 4. 核心用户故事

### US-001 自由表达与增量提取

用户可以用自然语言描述需求。系统提取本轮明确出现的信息，不确定信息保持未知或推断，不得擅自补全。

### US-002 动态追问

系统根据当前画像、阻断项、冲突和候选区分度，每轮选择一个最有信息价值的问题，而不是按固定问卷逐项询问。

### US-003 冲突处理

系统指出互相冲突的要求，解释现实代价，并让用户确认优先级；不得静默忽略任一已确认条件。

### US-004 双层推荐

系统先展示1至3个品种/类型方向，再展示0至3个关联的具体虚构宠物档案。候选不足时允许少于2个或为0，不得为凑数放宽硬约束或编造档案。

### US-005 诚实劝退或暂缓

当条件不适合立即养宠时，系统停止购买导向，解释原因并提供可执行的前置准备或替代体验。

### US-006 修改与重算

用户可以修改已确认条件。系统保留其他条件，重新检查冲突、过滤、排序和等级，并说明推荐变化。

### US-007 会话恢复与重置

用户可以在最近成功活动后的24小时内在同一Demo环境恢复会话，也可以主动重置并从空画像开始。

### US-008 完整原型浏览

体验者可以访问所有主要页面，明显按钮均有可理解反馈，未开放业务动作不会伪装为真实成功。

## 5. Agent状态契约

### 5.1 ConversationState

内部状态必须使用明确Schema，禁止使用无约束散乱字典。字段语义如下：

```json
{
  "schemaVersion": "string",
  "conversationId": "string",
  "revision": 0,
  "stage": "NEW|DISCOVERING|RESOLVING_CONFLICT|READY_TO_MATCH|MATCHING|RECOMMENDED|NOT_RECOMMENDED|COMPLETED|EXPIRED|RESET",
  "recommendationMode": "NONE|PROVISIONAL|FINAL",
  "messages": [],
  "profile": {},
  "missingCriticalSlots": [],
  "activeBlockers": [],
  "conflicts": [],
  "questionHistory": [],
  "consecutiveUnclearTurns": 0,
  "retrievedSourceIds": [],
  "directionCandidates": [],
  "petCandidateIds": [],
  "recommendations": null,
  "safetyFlags": [],
  "createdAt": "date-time",
  "lastActiveAt": "date-time",
  "expiresAt": "date-time"
}
```

约束：

- `revision`从0开始；每次成功消息处理或画像修改后加1。
- `expiresAt = lastActiveAt + 24小时`。创建、成功消息和成功画像修改会刷新；只读请求、失败请求和健康检查不刷新。
- `EXPIRED`和`RESET`为终态，不能继续写入。
- `MATCHING`失败时回到处理前的可恢复状态，不得留下半更新推荐。
- 内部候选允许包含数字分，但公共响应模型不得包含该字段。

### 5.2 SlotValue

每个关键槽位使用统一包裹结构：

```json
{
  "value": "typed value or null",
  "status": "UNKNOWN|INFERRED|CONFIRMED|DECLINED|CONFLICTED",
  "constraintStrength": "HARD|PREFERENCE|UNSET",
  "sourceMessageIds": [],
  "updatedAt": "date-time"
}
```

合并规则：

1. 用户直接、明确表达的值记为`CONFIRMED`。
2. 由含糊语言映射出的值记为`INFERRED`；推断值不能独自满足最终推荐的关键槽位。
3. 用户明确“不确定/不想回答”记为`DECLINED`，不得伪造默认值；可以产生暂定建议，但要列为待确认风险。
4. 新信息与已确认值不一致时记为`CONFLICTED`并进入澄清，不得静默覆盖。
5. 用户通过画像修改接口明确更新时，新值记为`CONFIRMED`，旧冲突关闭并重新计算。
6. `constraintStrength=HARD`表示不可妥协；未明确强度时，安全相关槽位按本规格硬规则处理，外观类默认`PREFERENCE`。

## 6. 状态转换与事务边界

| 当前状态 | 事件 | 条件 | 下一状态 | 必须产生的结果 |
|---|---|---|---|---|
| NEW | 创建成功 | 始终 | DISCOVERING | 欢迎语和一个首问 |
| DISCOVERING | 消息成功 | 出现冲突 | RESOLVING_CONFLICT | 冲突解释和一个澄清问题 |
| DISCOVERING | 消息成功 | 有关键缺失 | DISCOVERING | 一个动态问题 |
| DISCOVERING | 消息成功 | 信息足够 | READY_TO_MATCH | 可立即进入匹配 |
| RESOLVING_CONFLICT | 消息成功 | 冲突未解决 | RESOLVING_CONFLICT | 继续只澄清当前最高风险冲突 |
| RESOLVING_CONFLICT | 消息成功 | 冲突解决但仍缺信息 | DISCOVERING | 下一关键问题 |
| DISCOVERING | 用户要求直接推荐 | 无未解决会话级阻断或冲突 | MATCHING | 按未知不利原则执行硬过滤，结果只能是PROVISIONAL或NOT_RECOMMENDED |
| READY_TO_MATCH | 匹配开始 | 无阻断项 | MATCHING | 状态事务开始 |
| MATCHING | 有合理候选 | 关键槽位完整 | RECOMMENDED | FINAL双层建议 |
| MATCHING | 用户要求直接推荐 | 无未解决会话级阻断 | RECOMMENDED | PROVISIONAL双层建议和待确认项 |
| MATCHING | 无合理候选或阻断成立 | 始终 | NOT_RECOMMENDED | 原因和替代行动 |
| RECOMMENDED | 修改画像 | 产生冲突/缺失 | RESOLVING_CONFLICT或DISCOVERING | 旧推荐标记失效 |
| RECOMMENDED | 修改画像 | 仍可匹配 | MATCHING | 重新计算并给变化摘要 |
| 任意可写状态 | 主动结束 | 用户确认结束 | COMPLETED | 保留至过期但不再自动追问 |
| 任意非终态 | 24小时无成功活动 | 始终 | EXPIRED | 后续写请求返回会话过期 |
| 任意非终态 | 主动重置 | 始终 | RESET | 旧会话立即失效 |

一次消息处理是原子操作：画像、问题历史、消息、推荐、`revision`和过期时间要么一起成功，要么全部保持原值。

## 7. 硬约束规则

### 7.1 三种处理结果

- 会话级阻断：未解决前不能给最终推荐。
- 候选级排除：只排除违反该条件的方向或具体档案。
- 必须澄清：信息未知、含糊或冲突时先问，不把推测当事实。

### 7.2 基线规则表

| 约束 | 触发条件 | 处理 |
|---|---|---|
| 养宠许可 | `petAllowed=NO` | NOT_RECOMMENDED；不展示购买导向 |
| 养宠许可不确定 | `petAllowed=UNCERTAIN/UNKNOWN` | 优先追问；不能产出FINAL |
| 家庭同意 | 关键共同居住者明确反对 | NOT_RECOMMENDED或要求先取得一致 |
| 严重过敏 | `allergyLevel=SEVERE`且风险未由专业人员评估 | 会话级阻断；不得推荐“不过敏品种” |
| 一般过敏 | `MILD`或含糊 | 澄清接触反应与专业建议；相关候选显示风险，不能承诺低敏等于不过敏 |
| 稳定照护 | 无稳定照护人或安排 | NOT_RECOMMENDED |
| 陪伴/独处 | 候选最低陪伴需求高于用户可稳定提供值 | 排除该候选 |
| 运动能力 | 候选最低运动需求高于用户可稳定提供值 | 排除该候选 |
| 月度预算 | 候选基础成本下限高于用户确认的硬预算上限 | 排除该候选；全部被排除则NOT_RECOMMENDED或建议调整 |
| 突发医疗准备 | 明确未准备 | 可给PROVISIONAL，但必须提示准备方案；不能单独包装为FINAL |
| 空间/规定 | 候选体型、叫声或活动要求违反明确住房规则 | 排除该候选 |
| 家庭安全 | 档案明确不适合当前儿童年龄、老人或其他宠物 | 排除该候选；信息含糊则先澄清 |
| 负担容忍 | 用户将掉毛、叫声、气味或美容标为HARD且候选超过上限 | 排除该候选 |
| 来源偏好 | 用户明确只领养或只购买并标为HARD | 排除来源不符的具体档案 |

说明：

- 硬约束必须在内部评分前执行。
- 任何软偏好分都不能重新纳入被排除候选。
- “暂不建议”针对当前条件，不等于永久不适合养宠。
- 医疗相关内容只提示一般风险和寻求专业意见，不诊断。

### 7.3 必测冲突

至少识别：

- 长期独处但要求高度黏人。
- 不能接受掉毛但指定高掉毛方向。
- 硬预算较低但指定高基础成本方向。
- 可提供运动时间很少但指定高运动需求犬。
- 住房禁养但要求立即给购买链接。
- 家庭成员反对但用户要求跳过确认。
- 严重过敏但要求“绝对不过敏”的猫狗。
- 同一槽位前后给出互斥值。

冲突响应必须包含：冲突的两个事实、现实影响、一个需要用户决定的问题。不得一次抛出多个冲突问题。

## 8. 推荐就绪条件

### 8.1 最终推荐的关键槽位组

进入FINAL匹配前，以下槽位组必须有明确、非冲突且可用于判断的值：

1. 养宠许可与共同居住者同意
2. 过敏与家庭安全
3. 稳定照护安排、陪伴和独处能力
4. 可提供运动时间
5. 月度预算与突发医疗准备状态
6. 居住空间及明确限制
7. 家庭成员和其他宠物
8. 至少一组负担接受度：掉毛、叫声、气味或美容

猫狗偏好可以是“都可以”；软外观偏好不是FINAL前置条件。

### 8.2 暂定推荐

用户要求“直接推荐”时：

- 未解决的会话级阻断和当前冲突不能跳过。
- 可跳过非阻断的关键缺失并进入PROVISIONAL。
- 页面必须展示“暂定建议”、待确认项以及这些信息可能如何改变结果。
- 暂定建议仍必须经过硬过滤；未知不能被假设为有利条件。
- 用户补充或修改条件后必须重新匹配，不能只重写解释。

## 9. 动态追问契约

### 9.1 问题池

每个问题定义：

```json
{
  "questionId": "string",
  "targetSlots": [],
  "category": "BLOCKER|CONFLICT|CRITICAL|DISCRIMINATING|PREFERENCE",
  "fixedOrder": 0,
  "promptTemplateId": "string",
  "quickReplies": []
}
```

### 9.2 选择算法

每轮按以下顺序选一个问题：

1. 可通过用户回答解决的活动阻断项。
2. 当前最高风险且最早出现的冲突。
3. 缺失的关键槽位。
4. 能最大幅度区分剩余方向/候选的非关键问题。
5. 软偏好。

同一层级按以下稳定规则排序：

1. 预计能排除的候选数从高到低。
2. `fixedOrder`从小到大。
3. `questionId`字典序。

约束：

- 已有`CONFIRMED`值的目标槽位不能重复问，除非用户修改相关信息或产生新冲突。
- `INFERRED`值允许用确认式问题核实。
- `DECLINED`槽位本轮不重复追问；若它阻止FINAL，只能给PROVISIONAL并显示风险。
- 每轮默认只输出一个问句，可带3至5个快捷选项和自由输入。
- 快捷选项只是便利入口，不能改变自由文本的同等处理权。
- 同一`questionId`不能重复，除非前一次回答无法理解或相关条件后来被修改。
- 连续两次无法理解时，返回改写示例和重置入口，不继续循环同一问法。

### 9.3 为什么这不是固定问卷

自动化测试必须证明：

- 一次性已给出住房和过敏信息时，后续不再询问这两项。
- 同样的初始问题，在不同首轮回答下产生不同第二问。
- 新冲突出现时，原定软偏好问题被中断，先处理冲突。
- 用户修改已确认条件后，允许围绕受影响条件重新澄清。

## 10. 双层推荐与匹配等级

### 10.1 第一层：品种/类型方向

输出1至3项，每项包含：

- `directionId`
- 名称和“品种”或“类型”标记
- 用户可见匹配等级
- 适合原因
- 需要接受的代价
- 潜在不匹配点
- 一般照护需求和成本区间
- 证据来源ID
- “群体倾向不代表具体个体”的提示

不得为了展示纯种品种而忽略更稳妥的混种、成年或行为记录型方向。

### 10.2 第二层：具体虚构宠物档案

输出0至3项，每项必须：

- 引用数据集中存在的`petId`。
- 关联一个`directionId`。
- 单独通过全部硬约束。
- 使用个体档案事实解释，不把品种倾向冒充个体事实。
- 包含匹配等级、适合原因、代价、不匹配点、已知注意事项和进一步线下了解建议。

方向可成立但没有合格具体档案时，允许第二层为空，并明确“当前Demo档案暂无合适个体”。

### 10.3 内部评分和等级映射

硬过滤通过后，内部数字分用于稳定排序与评测，基线维度为：

- 时间与陪伴适配：20
- 活动与运动适配：15
- 空间适配：15
- 预算适配：15
- 家庭成员与其他宠物：15
- 掉毛、叫声、气味与美容：10
- 经验要求：5
- 外观与来源偏好：5

总分0至100，是Demo产品假设，不是科学结论。

基线等级：

| 内部分数 | 公共枚举 | 页面文案 | 展示规则 |
|---|---|---|---|
| 80-100 | HIGH | 较匹配 | 可展示 |
| 65-79 | MEDIUM | 可考虑 | 可展示 |
| 50-64 | CAUTION | 需谨慎 | 只在不匹配点和代价足够明确时展示 |
| 0-49 | 不对外输出 | 不展示 | 不进入推荐列表 |

稳定排序：内部分数降序 -> 不匹配点数量升序 -> `petId`或`directionId`字典序。

权重或阈值改变属于业务行为变化，必须先修订规格和回归测试。

### 10.4 公共输出禁止项

页面、浏览器日志和公共API响应均不得包含：

- `matchScore`、`rawScore`或任何精确数字分
- 模型思维链
- 系统Prompt
- API Key或提供方敏感配置
- 不存在于数据集的宠物档案
- 无来源的确定性健康、性格或低敏承诺

## 11. 知识与虚构数据契约

### 11.1 知识条目

首版只覆盖猫和狗。每条知识至少包含：

- `sourceId`
- 标题、主题和适用对象
- 重新编写的正文
- 来源名称、来源链接或可追溯出处
- 发布时间或未知标记
- 本地复核日期
- 适用边界

最终推荐中的事实性养护结论必须能追溯到`sourceId`。检索无结果时不得让LLM补造来源。

### 11.2 方向档案

至少12个常见猫犬品种或类型方向，包含群体倾向、适用条件、典型负担、健康与养护风险、不可保证事项和来源。

### 11.3 具体宠物档案

至少24个虚构档案，每个包含：

- ID、昵称、物种、品种/类型、年龄阶段、性别
- 体型、活动量、最低运动需求、独处能力、陪伴需求
- 掉毛、叫声、气味、美容和经验要求
- 月度基础成本区间
- 儿童、老人、其他宠物和住房适配标签
- 个体观察的来源类型和观察时间范围
- 已知注意事项
- 领养、转让或模拟售卖标记
- 图片来源或占位图

“未知”必须显式记录，不能用理想值填补。

## 14. API端点

### 14.1 创建会话

`POST /api/v1/conversations`

请求：

```json
{
  "clientLocale": "zh-CN"
}
```

`clientLocale`可省略，首版只接受`zh-CN`。

成功：`201 Created`

```json
{
  "data": {
    "conversation": {},
    "assistantMessage": {},
    "nextQuestion": {
      "questionId": "permission_or_housing",
      "text": "string",
      "quickReplies": []
    }
  },
  "meta": {
    "requestId": "string"
  }
}
```

验收：创建后`revision=0`、`stage=DISCOVERING`、画像全为未知、`expiresAt`为创建时间后24小时。

### 14.2 发送消息

`POST /api/v1/conversations/{conversationId}/messages`

请求：

```json
{
  "clientMessageId": "client-generated-unique-id",
  "baseRevision": 0,
  "content": "用户文本",
  "quickReplyId": null
}
```

约束：

- `content`去除首尾空白后为1至2000个Unicode字符。
- `quickReplyId`可空；存在时必须属于当前问题。
- 相同会话和`clientMessageId`重复提交返回第一次成功结果，不重复增加消息、轮次或刷新两次状态。
- `baseRevision`不等于服务端当前值时返回`409 REVISION_CONFLICT`。

成功：`200 OK`，返回：

```json
{
  "data": {
    "conversation": {},
    "assistantMessage": {},
    "profileChanges": [],
    "nextQuestion": null,
    "quickReplies": [],
    "recommendation": null,
    "warnings": []
  },
  "meta": {
    "requestId": "string"
  }
}
```

`nextQuestion`和`recommendation`最多一个非空。推荐对象遵守第15节，不能含内部分数。

### 14.3 获取会话

`GET /api/v1/conversations/{conversationId}`

成功：`200 OK`，返回公共会话摘要、可展示消息、当前问题和当前推荐；只读请求不刷新24小时期限。

### 14.4 修改画像

`PATCH /api/v1/conversations/{conversationId}/profile`

请求：

```json
{
  "baseRevision": 3,
  "updates": {
    "monthlyBudgetCny": {
      "value": 800,
      "constraintStrength": "HARD"
    }
  }
}
```

规则：

- 只接受白名单槽位和合法值。
- 用户修改值记为`CONFIRMED`。
- 成功后`revision+1`并刷新24小时期限。
- 旧推荐立即失效；服务端同步完成冲突检查和重新匹配或返回下一澄清问题。
- 返回`profileChanges`和`recommendationChanges`，说明新增、移除、等级变化或转为暂定。

### 14.5 获取推荐

`GET /api/v1/conversations/{conversationId}/recommendations`

- `RECOMMENDED`或`NOT_RECOMMENDED`时返回`200`。
- 尚未形成建议时返回`409 RECOMMENDATION_NOT_READY`。
- 响应只包含公共推荐模型，不含数字分。

### 14.6 主动重置

`DELETE /api/v1/conversations/{conversationId}`

- 成功返回`204 No Content`。
- 旧会话立即标记`RESET`且不可恢复。
- 前端随后显式调用创建会话接口；服务端不暗中复用旧ID。
- 重复删除已经重置的会话仍返回`204`，保证幂等。
- 重置后的旧ID用于读取或写入时返回`404 CONVERSATION_NOT_FOUND`。

### 14.7 健康检查

`GET /health`

返回服务存活和必要依赖的非敏感状态，不返回模型名、Key、环境变量值或内部路径。

## 16. HTTP错误语义

| HTTP | code | retryable | 场景 |
|---|---|---|---|
| 400 | INVALID_REQUEST | false | JSON结构错误 |
| 404 | CONVERSATION_NOT_FOUND | false | ID不存在或已重置 |
| 409 | REVISION_CONFLICT | true | 客户端版本落后 |
| 409 | RECOMMENDATION_NOT_READY | false | 尚未形成推荐 |
| 410 | SESSION_EXPIRED | false | 24小时无成功活动 |
| 422 | VALIDATION_ERROR | false | 文本为空、超长或字段语义非法 |
| 422 | INVALID_QUICK_REPLY | false | 快捷选项不属于当前问题 |
| 429 | RATE_LIMITED | true | 模型或服务限流 |
| 502 | MODEL_INVALID_RESPONSE | true | 提供方响应未通过Schema |
| 503 | MODEL_UNAVAILABLE | true | 模型超时或不可用 |
| 503 | KNOWLEDGE_UNAVAILABLE | true | 必要知识源无法读取 |
| 500 | INTERNAL_ERROR | true | 未分类服务错误 |

模型或知识错误不得提交半成品状态；重试使用原`baseRevision`。

## 20. TDD与测试策略

### 20.1 强制顺序

## 21. 可测试验收标准

以下均为后续实现与验收目标，不代表当前已实现。

### AC-001 跳过已知信息

- Given：首轮明确说明允许养宠、无过敏、住小户型。
- When：系统处理成功。
- Then：后续问题不再询问许可、过敏和住房；`profile`相应槽位为`CONFIRMED`。

### AC-002 分支不同

- Given：两个空会话。
- When：A回答“房东不确定是否允许”，B回答“允许，但每天只能陪伴1小时”。
- Then：A下一问优先确认许可，B下一问进入照护能力；`questionId`不同。

### AC-003 每轮一个问题

- Given：同时缺少多个关键槽位。
- When：系统生成下一轮。
- Then：只有一个`nextQuestion`和一个`questionId`，快捷选项不超过5个。

### AC-004 冲突抢占

- Given：用户已确认每天长期独处，又要求高度黏人。
- When：冲突被检测。
- Then：状态为`RESOLVING_CONFLICT`；下一问澄清该冲突，不询问外观偏好。

### AC-005 已确认值保护

- Given：预算已由用户确认。
- When：模型下一轮输出不同预算但用户没有表达修改。
- Then：原值不被覆盖，产生冲突或拒绝该增量。

### AC-006 住房禁养

- Given：`petAllowed=NO`。
- When：用户要求直接推荐。
- Then：返回`NOT_RECOMMENDED`，候选为空，不展示购买主行动，并解释前置条件。

### AC-007 严重过敏

- Given：严重过敏且未获得专业评估。
- When：进入推荐判断。
- Then：不能返回FINAL，不能出现“绝对不过敏”或等价承诺。

### AC-008 候选硬排除

- Given：用户最多每天运动20分钟，候选最低要求90分钟。
- When：执行过滤与排序。
- Then：该候选不进入评分和公共推荐。

### AC-009 预算不可抵消

- Given：候选基础成本下限高于用户硬预算，但外观偏好完全匹配。
- When：执行推荐。
- Then：候选仍被排除，外观分不能抵消预算硬约束。

### AC-010 直接推荐降级

- Given：无活动阻断或冲突，但有非阻断关键槽位未知。
- When：用户要求直接推荐。
- Then：返回`PROVISIONAL`，列出待确认项和可能影响，不伪造完整画像。

### AC-011 两层推荐

- Given：存在合格方向和具体档案。
- When：推荐完成。
- Then：返回1至3个方向和最多3个宠物；每个宠物关联现有`directionId`和数据集`petId`。

### AC-012 档案不足不凑数

- Given：只有1个具体档案通过硬约束。
- When：推荐完成。
- Then：只返回1个具体宠物，不放宽约束、不编造第二个；方向层仍可独立展示。

### AC-013 无档案但有方向

- Given：存在合理类型方向，但没有具体档案通过硬约束。
- When：推荐完成。
- Then：方向可返回，`pets=[]`，页面说明当前Demo档案暂无合适个体。

### AC-014 不暴露精确分

- Given：内部已计算数字分。
- When：获取消息、会话或推荐API，或渲染结果页。
- Then：JSON和页面中不存在`matchScore`、`rawScore`或0至100匹配数字，只出现匹配等级。

### AC-015 等级映射与排序

- Given：通过硬过滤的内部得分为82、70、55、49。
- When：映射和排序。
- Then：前三者依次为HIGH、MEDIUM、CAUTION；49分候选不输出；相同分按稳定次序排列。

### AC-016 条件修改重算

- Given：已形成推荐。
- When：用户将月预算改为更低的硬上限。
- Then：旧推荐失效，完整重跑过滤与排序，返回候选新增/移除/等级变化摘要。

### AC-017 消息幂等

- Given：同一`clientMessageId`成功提交两次。
- When：第二次到达。
- Then：返回第一次结果；消息数、`revision`和状态只变化一次。

### AC-018 Revision冲突

- Given：服务端`revision=4`，客户端提交`baseRevision=3`。
- When：执行写请求。
- Then：返回`409 REVISION_CONFLICT`，状态不变。

### AC-019 24小时滑动过期

- Given：会话在T0创建，T0+20小时成功发送消息。
- When：读取过期时间。
- Then：`expiresAt`更新为该成功消息时间后24小时；只读请求不延长。

### AC-020 会话过期

- Given：最近成功活动超过24小时。
- When：继续发送消息。
- Then：返回`410 SESSION_EXPIRED`，状态不变，前端提供新建会话入口。

### AC-021 主动重置

- Given：已有画像和推荐。
- When：调用重置。
- Then：返回204；旧ID不可读写；新建会话画像为空且不继承旧数据。

### AC-022 Mock确定性

- Given：相同夹具、输入和调用序列重复运行两次。
- When：使用Mock。
- Then：结构化输出一致，不访问网络，不读取或消耗DeepSeek Key。

### AC-023 Mock边界真实

- Given：Mock返回画像增量。
- When：完成推荐流程。
- Then：槽位合并、冲突、问题选择、知识检索、过滤、评分、等级和API Schema均走生产同路径。

### AC-024 模型失败回滚

- Given：消息处理前`revision=2`。
- When：DeepSeek超时或返回无效Schema。
- Then：返回对应可重试错误；`revision`、消息、画像、推荐和过期时间保持处理前值。

### AC-025 知识无结果

- Given：必要知识检索在一次受控的扩大查询后仍无结果。
- When：生成推荐。
- Then：不提交推荐和状态变更；返回`503 KNOWLEDGE_UNAVAILABLE`，不编造来源、方向或具体档案。

### AC-026 连续无法理解

- Given：连续两轮输入都无法映射到当前问题。
- When：第二次失败。
- Then：提供改写示例和重置入口，不无限重复原问题。

### AC-027 原型边界

- Given：用户点击支付、合同、物流、发帖或会员确认。
- When：动作触发。
- Then：显示“Demo演示功能，暂未开放”，不创建真实业务数据。

### AC-028 五轮动态演示

- Given：一个信息不足的新手场景。
- When：完成至少5轮对话。
- Then：问题随状态变化、已知项被跳过、至少处理一个硬约束或冲突，并形成FINAL、PROVISIONAL或NOT_RECOMMENDED之一。

## 24. 失败与降级

- DeepSeek不可用：保留处理前状态，提示重试，不伪造推荐。
- 模型结构无效：校验失败并返回可重试错误，不让自由文本绕过业务Schema。
- 知识无结果：先执行一次受控的扩大查询；仍无结果则回滚本轮推荐事务并返回`KNOWLEDGE_UNAVAILABLE`，前端可另行展示不依赖推荐结论的通用准备建议。
- 无符合候选：解释哪些硬约束排除了候选，允许用户修改，但不施压放宽。
- 输入无法理解：先改写澄清；连续两次后提供示例和重置。
- 会话过期：不恢复旧状态，提供创建新会话入口。
- 前端接口失败：显示可重试状态，不能无限加载。
- 推荐解释安全复核失败：不发布未复核文案，返回安全降级模板或可重试错误。
